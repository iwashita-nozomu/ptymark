# ptymark v0.1.0-alpha.3

`v0.1.0-alpha.3` is a source-only prerelease focused on clean installation, reliable interactive terminal output, visible session state, and explicit structured-math input.

## Highlights

- Added explicit OpenMath XML fences and bounded local OpenMath-to-TeX conversion with exact-source recovery.
- Fixed managed renderer installation on clean Linux/WSL hosts without a global Node.js installation. The pinned private runtime now executes npm and its lifecycle scripts without modifying the user's global `PATH`.
- Fixed diagonal/right-shifted interactive rendering by converting lone LF bytes from successful renderer output to terminal-safe CRLF. Child output, ANSI/control traffic, existing CRLF, and fallback source remain byte-exact.
- Added the stable `PTYMARK_ACTIVE=1` marker to interactive child processes on Unix PTY and Windows ConPTY backends.
- Accidental nested sessions are rejected by default. `--allow-nested` remains available explicitly for development and debugging.
- Added opt-in `[ptymark]` prompt examples without editing shell startup files automatically.

## Install from the released source

```bash
git clone --branch v0.1.0-alpha.3 --recurse-submodules https://github.com/iwashita-nozomu/ptymark.git
cd ptymark
bash scripts/installer.sh
```

Then verify the installation:

```bash
ptymark --version
ptymark install status
ptymark config check
ptymark engine check
ptymark doctor
```

On Windows, use the documented PowerShell or `installer.cmd` source-install route.

## Interactive session visibility

Inside `ptymark -- COMMAND`, child processes receive:

```text
PTYMARK_ACTIVE=1
```

A shell prompt may display `[ptymark]` conditionally, but Ptymark does not modify `.bashrc`, `.zshrc`, Fish, Nushell, PowerShell, or prompt-framework configuration.

## Source-only distribution

This release intentionally contains no project-uploaded executable archives, installer bundles, binary checksums, binary manifests, or executable-bearing artifacts. GitHub provides the immutable tag, these notes, and its generated source-code snapshots. Build locally from the reviewed tag or use a separately trusted downstream packaging channel.

Source-only distribution avoids presenting unsigned and unnotarized project binaries as an operating-system-trusted channel; it does not make a local build automatically trusted. Review the source, lockfiles, toolchain, and dependencies appropriate to your environment.

## Known limitations

- Semantic blocks emitted interactively must start on a clean logical line. When prompt/control traffic shares the line, emit a leading newline before the opening delimiter.
- This remains an alpha release. Guided setup, complete CJK/grapheme/accessibility behavior, lifecycle commands, signed package channels, persistent renderer workers/cache, and terminal image protocols remain follow-up work.
